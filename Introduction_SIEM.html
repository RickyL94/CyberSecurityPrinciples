SEG 1 · HOOK
Correlation Scenario

One user, four events — each benign in isolation. Read together:

14:02
Haris logs in via VPN from an unfamiliar external IP address
14:07
Haris accesses sensitive financial spreadsheets on the shared file drive
14:11
Haris executes an encoded PowerShell script on his workstation
14:16
Workstation initiates outbound connection: 25 MB transferred in 30 seconds

Verdict: Probable Data Exfiltration via Compromised VPN Credentials. No single host or network device flagged an error. Only cross-source event correlation reveals the attack sequence.

SEG 2 · WHAT IS SIEM
Definition

SIEM: Security Information and Event Management

Security Information Management (SIM): Long-term log collection, storage, and analysis for compliance and reporting.

Security Event Management (SEM): Real-time monitoring, event correlation, and immediate alerting on suspicious behaviour.

  • SIEM Combines Both: Aggregates logs across the entire estate, normalises formats, correlates events, and triggers actionable security alerts.

SEG 3 · CHECKPOINT
Telemetry Review

Categorisation Summary

Host-Centric Logs: Generated locally on endpoints and servers (e.g., Windows Event Logs, Sysmon, Linux `/var/log/auth.log`). Captures process execution, registry edits, local authentication, and file modifications.

Network-Centric Logs: Generated by infrastructure devices (e.g., Firewalls, Routers, Switches, Proxies, IDPS). Captures IP traffic, packet flows, VPN sessions, and web requests across the wire.

SEG 5 · WHY SIEM
Core Capabilities

The Four Pillars of SIEM Architecture

01

Centralised Collection

Pulls telemetry continuously from all endpoints, servers, cloud feeds, and network assets into one central repository.

02

Parsing & Normalisation

Extracts unstructured raw log text into structured key-value pairs using a unified Common Information Model (CIM).

03

Real-Time Correlation

Links events from disparate systems across time windows to detect complex threat behaviours.

04

Detection & Alerting

Executes continuous detection rules and triggers prioritised alerts for security analyst triage.

SEG 5 · FEATURE
Data Transformation

Parsing and Field Normalisation

Parsing: Breaking down raw, unstructured text log strings into distinct schema fields (e.g., `src_ip`, `dest_port`, `user`).

Normalisation: Standardising vendor-specific labels into a consistent taxonomy. For example, mapping Cisco's `src`, Palo Alto's `Source_IP`, and Windows' `SourceAddress` all into the single standard field: src_ip.

  • Essential Requirement: Detection rules rely on field-value pairs. Without normalisation, rules would need to be written 50 times for 50 different vendors.

SEG 5 · FEATURE
Rule Types

Detection Mechanics & Alert Triggers

STATIC THRESHOLD

Frequency Rules

Triggers when an event count exceeds a defined threshold within a time window (e.g., >5 failed logins in 10 seconds).

BEHAVIOURAL BASELINE

Anomaly Detection

Triggers when user or entity behaviour deviates from historical baselines (e.g., first-time VPN login from new country).

SEQUENCE CORRELATION

Multi-Stage Rules

Triggers when a specific sequence of events occurs across different log sources in chronological order.

SEG 7 · INGESTION
Data Forwarding

Primary Ingestion Pipelines

  • Universal Forwarder (UF): Dedicated agent installed on target endpoints. Highly reliable, compressed, and encrypted log streaming.
  • Syslog (UDP/TCP Port 514): Standard protocol used by network gear, firewalls, and Linux daemons to stream logs directly to indexers or syslog collectors.
  • HTTP Event Collector (HEC): Token-based REST API interface for streaming JSON formatted telemetry from cloud services and applications over HTTPS.
  • Manual Upload: Direct file upload (.csv, .log) via Splunk Web for offline forensics and temporary analysis.
SEG 7 · CHECKPOINT
Review

Ingestion Selection Strategy

Production Endpoints & Servers: Always deploy the Splunk Universal Forwarder for reliable, encrypted streaming.

Network Appliances (Firewalls/Switches): Forward via Syslog (UDP/TCP 514) to a dedicated Syslog-ng/RSyslog aggregator.

Cloud Native Services & Serverless: Push events via HTTP Event Collector (HEC) REST endpoints.

SEG 8 · DETECTION RULES
Rule Example 01

Detecting Audit Event Log Clearing

Adversaries clear audit logs to remove forensic artifacts following compromise.

IF Log_Source == "WinEventLog:Security" AND EventID == 1102
THEN TRIGGER ALERT "Windows Security Audit Log Cleared" [Severity: Critical]

Rule Mechanics: Operates on exact field-value matching. Requires zero correlation window as a single occurrence indicates malicious intent or policy violation.

SEG 8 · DETECTION RULES
Rule Example 02

Detecting Reconnaissance Executables

Adversaries execute utility commands like `whoami` or `net group` immediately following initial access.

IF Log_Source == "WinEventLog:Security" AND EventID == 4688
AND NewProcessName ENDS_WITH "whoami.exe"
THEN TRIGGER ALERT "Reconnaissance Process Execution (whoami)" [Severity: Medium]

Normalisation Dependency: Requires the indexer to have successfully parsed `EventID` and `NewProcessName` from raw process execution event logs.

SEG 8 · TRIAGE
Analyst Workflow

The 60-Second Alert Triage Standard

01
Inspect Raw Event Telemetry: Open the search results backing the alert to verify match accuracy.
02
Evaluate Rule Logic & Context: Check time windows, host roles, user permissions, and asset criticality.
03
Render Triage Verdict: Classify official verdict as True Positive (TP) or False Positive (FP).
SEG 8 · POST-VERDICT
Remediation & Tuning

Post-Triage Action Paths

TRUE POSITIVE

Incident Response Path

1. Isolate compromised endpoint from network.
2. Revoke compromised user credentials.
3. Escalate to Tier-2 / Incident Response team.

FALSE POSITIVE

Rule Tuning Path

1. Document benign business reason.
2. Update detection search syntax with exclusions.
3. Prevent future alert fatigue.

SEG 10 · WRAP
Summary

Core Takeaways

1. SIEM Solves Fragmentation: Centralises, normalises, and correlates logs from disparate enterprise assets.

2. Normalisation is Essential: Parsing logs into standard key-value fields enables scalable detection rules.

3. Continuous Triage Loop: Detection rules generate alerts → analysts triage events → true positives are contained, false positives tune the rules.
